# 編號邏輯: NumberingLogic

## suggestIssueSetKey 產生 KEY 建議值

- 建立工單集時產生 KEY 建議值，供呼叫端作為預設值
- **輸入:**
  - 所屬產品名稱
  - 工單集名稱
- **執行:**
  - 依產品名稱與工單集名稱組出建議值
  - 建議值須符合 `validateIssueSetKey` 的字元規則
- **回傳:**
  - 建議值，使用者可修改

---

## validateIssueSetKey 驗證工單集 KEY

- 建立工單集時驗證使用者指定的 KEY
- **輸入:**
  - 使用者指定的 KEY
  - 所屬 Company 租戶鍵
- **執行:**
  - **IF** KEY 長度不在二到八字元:
    - **回傳:** 錯誤，中止並要求修改
  - **IF** KEY 含大寫英文與數字以外的字元:
    - **回傳:** 錯誤，中止並要求修改
  - **IF** KEY 以數字開頭:
    - **回傳:** 錯誤，中止並要求修改；數字開頭會與流水號無法區隔
  - **IF** 同一 Company 內已存在相同 KEY:
    - **回傳:** 錯誤，撞號中止並要求改用其他 KEY；Company 即租戶邊界，KEY 唯一範圍以租戶為界
  - **ELSE:**
    - **回傳:** 全數檢查通過，KEY 可用

---

## assignIssueKey 產生工單編號

- 建立工單時產生編號，格式為前綴加連字號加流水號，例如 `LSPEC-142`
- **輸入:**
  - 新工單所屬的工單集
- **取前綴:**
  - **執行:**
    - 取所屬工單集的 KEY 作為前綴
  - **理由:**
    - 編號的價值在不必讀取工單內容即知出處
    - 工單集是階段，階段是最常需要辨識的維度
- **取流水號:**
  - **執行:**
    - 於所屬工單集以 `IssueSets.nextSeq` 遞增取號
  - **行為:**
    - `IssueSets.nextSeq` 每個工單集各自一份，不跨工單集
    - 序列只前進，工單刪除後其號不回收
- **編號不變性:**
  - **行為:**
    - 編號產生後永不變更
    - 工單移至其他工單集仍保留原號，不重新編號
    - 現行所屬工單集由所屬關係回答，不由編號前綴回答
  - **理由:**
    - 重新編號會讓所有既有連結失效，代價高於前綴與現況不符
- **回傳:**
  - 產生的編號，寫入 `IssueKey` 欄位，該欄位由系統寫入
